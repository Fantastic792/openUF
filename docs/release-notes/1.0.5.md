## openUF 1.0.5

An upgrade now really switches openUF to the new version. Nothing else changes on the router.

### What got fixed

- **An upgrade left the old version running.** After upgrading openUF in LuCI (System >
  Software > Updates) or with `apk upgrade`, the new files were installed but openUF kept
  running the old version until the next reboot. The package's install steps had a name
  the OpenWrt build ignores, so they never ran in any 1.0.x package. They run now. With
  them, three more things come back: a warning when the router's Wi-Fi software
  (wpad) is the basic build or the `luasec` package is missing, the clean-up of the old
  802.11r helper, and, when openUF is removed, the clean-up of its user account, cron
  entries and network entries.

### How to upgrade

In LuCI: System > Software > Update lists..., then the Updates tab: upgrade `openuf`, then
`luci-app-openuf`. Or over SSH: `apk update && apk upgrade`.

This upgrade itself restarts openUF on 1.0.5: the new package brings the fixed step with it.
If you upgraded to 1.0.4 or older before, and never rebooted since, that router may still
be running the version before it. Upgrading to 1.0.5 sorts it out.

### Known issues

- Upgrading `luci-app-openuf` in LuCI shows "Unable to execute apk upgrade command: XHR
  request aborted by browser". The upgrade worked: it restarts the web server while
  LuCI is still waiting for the answer. Reload the page.
- **Transmit Power Low and Medium** run at full power. Auto, High and a custom value in dBm
  work.
- On the JioRouter AX6000 (JIDU6401) the controller's **LED off** shows no change: openUF
  drives the green part of the one LED, and OpenWrt keeps the red part lit. Locate works.

### For the technically minded

- `package/openuf/Makefile`: `define Package/openuf/postinst-pkg` and `prerm-pkg` renamed
  to `postinst` and `prerm`. OpenWrt's package-pack.mk writes `Package/<p>/postinst` and
  `/prerm` to the `postinst-pkg` / `prerm-pkg` files (opkg) or after `default_postinst`
  in the apk's scripts; a define with the `-pkg` name is never read. Found on a JioRouter
  AX6000 (JIDU6401): 1.0.3 -> 1.0.4 from LuCI left `inform.lua` running from boot, and the
  installed apk scripts held only `default_postinst`. `tools/test-packaging.sh` now refuses
  a `-pkg` define name.
- `tools/verify.py` logs in to the self-hosted Network application 10.x, which answers
  `/api/auth/login` with 401 `api.err.LoginRequired`.
- `labtest`: the push dump switches in UCI on a package install, and the feature table
  skips `WlanConf.setting_preference`: flipping it made the controller drop the WLAN's
  `short_id`, so the AP lost that WLAN until it was created again in the UI.
