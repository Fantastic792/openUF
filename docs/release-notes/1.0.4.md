## openUF 1.0.4

Small fixes to the install command. Nothing changes on a router that is already set up.

### What got fixed

- **The install command did not ask its questions.** Run as `wget -qO- ... | sh`, the
  installer downloads a second copy of itself so it can talk to your keyboard. On OpenWrt
  25.12 that download failed for the reason 1.0.2 fixed for the other downloads (the
  router's download tool cannot read github.com's answer), so the installer printed
  "could not re-fetch ... running with defaults for every question" and went on with the
  default answers. It now fetches that copy through GitHub's other address too, still
  checked against the signed checksum list.
- **A confusing line during the roaming install.** The rrb-unifi installer says "Confirm
  within 120s ... otherwise the previous network config is restored". openUF's installer
  already confirms it; it now says so, so you do not need to open a second SSH session.
- **The last screen said LuCI was behind a key sequence.** It now points at the *Open LuCI*
  button under Local Settings.

### How to upgrade

Nothing to do on a router that is already installed. New installs use the fixed command
as soon as this release is out.

### For the technically minded

- `setup.sh`: `self_fetch` (the piped re-exec's setup.sh, SHA256SUMS, SHA256SUMS.sig)
  falls back from `releases/latest/download/<file>` to the release JSON and `fetch_asset`'s
  API asset URL. Proven by `tools/test-packaging.sh` with stubs and on a JioRouter AX6000
  (the failure, 2026-11-24); the fixed path is not yet run on hardware.
- `labtest/extra/cycle.py`: `cycle.leftovers` no longer counts files owned by a package
  that is still installed (`/lib/apk/packages/*.list`, opkg's `*.list`): `install.sh
  uninstall` leaves lldpd, usteer, nftables and kernel modules on purpose.
- Full list of commits: compare `v1.0.3...v1.0.4` on GitHub.
