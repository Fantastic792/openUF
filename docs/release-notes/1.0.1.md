## openUF 1.0.1

A safety update for 1.0.0. **If you run 1.0.0, please upgrade.** Your settings are kept.

### What got fixed

- **A crash that someone on your network could trigger.** A specially made message,
  pretending to come from your UniFi controller, could make openUF use up all of the
  router's memory and bring the router down. It took someone already on your network to do
  this, but nobody should be able to crash your router at all. openUF now throws such
  messages away.
- **Guest WiFi rules could be missing.** On some guest networks, the rules that keep guests
  away from your own devices were not switched on. This happened only when the controller
  sent the guest network in an unusual way. openUF now recognises the network by its name and
  turns the rules on.

### Also in this release

- The lab tests that check roaming were made fairer. One test checks a phone moving
  between two working access points, and a separate test checks what happens when an access
  point suddenly disappears. The product itself did not change here.
- The README was rewritten to explain what openUF is, what has been tested and what has
  not, and who made the projects it is built on.

### How to upgrade

On the router, over SSH:

```sh
apk update && apk upgrade        # if you installed from the openUF package feed
openuf-update                    # any other install
```

### For the technically minded

- `inflate`: `MAX_OUTPUT` is 1 MiB, down from 8 MiB. The output is held one table slot per
  byte, so an 8 KB zlib bomb reached 162 MB RSS before the old cap (audit finding F-18).
- Guest rules: a guest WLAN with no `aaa.<n>.id` (a controller record without a
  `short_id`) is now keyed by SSID, and `wlanconf_ifnames` matches an openUF VAP with no id
  by that SSID (F-6).
- labtest: `roam` is a soft roam (`wpa_cli roam`, both APs up, limit `roam_max_s` 3 s); the
  hard cut is the new `ap_loss` check (limit `ap_loss_max_s` 10 s) (F-20).
- Full list of commits: compare `v1.0.0...v1.0.1` on GitHub.
